KEY ARCHITECTURAL INSIGHTS
================================================================================

#1: THE POLICY DOESN'T KNOW WHAT IT DOESN'T KNOW
    Policy trained on PERFECT sim data. Makes decisions with WRONG inputs
    when it sees real data (stale, noisy, invalid). This is an ENVIRONMENT
    BUG, not a policy bug. Fix the interface first.

#2: SIM-TO-REAL TRANSFER IS A DATA PROBLEM
    Edge cost model, reward function, task generator all assume simulator
    statistics. Real data has different distributions (multimodal delays,
    varying capacities, terrain effects). Need online adaptation layer.

#3: SAFETY COMES FROM GRACEFUL DEGRADATION, NOT PERFECTION
    Can't make system perfect. Real robots will fail. Real networks will
    drop packets. Real humans will interfere. System should:
      • DETECT failures (stale telemetry, invalid position)
      • DEGRADE gracefully (skip assignment, wait for recovery)
      • RECOVER automatically (when conditions improve)
      • ALERT humans (only when automatic recovery fails)

#4: RELIABILITY LAYER IS NOT OPTIONAL
    The 9 planned modules are LOAD-BEARING. Every gap is a failure mode.
    Prioritize:
      1. Telemetry validation (MUST do before deployment)
      2. Recovery flows (MUST work before connecting robots)
      3. Everything else in priority order
